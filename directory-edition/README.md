# Shopify App Builder — build your first Shopify app, one clear step at a time

A beginner-friendly Shopify app development plugin for Claude. You bring the merchant problem; the plugin helps Claude explain unfamiliar terms, recommend a sensible path, implement small testable changes and show evidence before calling something done.

It contains 36 focused skills, 17 guided commands and 8 specialist agents. No bundled MCP server, telemetry, required cloud account or hidden credentials.

> Independent community project. Not affiliated with, endorsed by or sponsored by Shopify. No guarantee of security, profitability, trademark clearance, App Store acceptance or Built for Shopify designation.

## Directory edition

This folder is the **text-only build for the Claude directory**. It contains only Markdown skills, commands and agents, JSON/YAML metadata and the icon. There are no scripts or programs. The full edition, with its offline helper and repository scripts, is installable from the GitHub repository: <https://github.com/khadinakbarlabs/shopify-app-builder> (the repository root is the full edition; this `directory-edition/` folder is the directory build).

**Works the same:** all 36 skills, 17 commands and 8 agents, with the same names and triggers; the Shopify guidance, references and examples; the Apify spending gate (show Actor, input, price and a monetary maximum, get approval, verify budget controls, no automatic paid retries); every approval rule for store writes, scopes, charges, deployment and submission.

**Less exact than the full edition (honest list):**

- **Project record writes** (`.shopify-app-builder/project.json`) are done by Claude with ordinary file tools instead of a helper. There is no file lock and no atomic write; the revision conflict check is a manual re-read-and-compare, so two sessions writing at once can lose a change.
- **Schema validation** (enums, 600-character caps, array caps, ID pattern, strict `YYYY-MM-DDTHH:MM:SS.sssZ` timestamps, verified-needs-evidence) is instruction-following rather than code-enforced, so malformed records are more likely. The schema-1 format is unchanged, so records from the full edition stay compatible.
- **Secret and contact filtering** before saving is a written pattern table Claude checks (GitHub, Shopify, Apify, AI-provider tokens, PEM keys, bearer headers, emails, credential URLs), not a fixed regular-expression gate.
- **doctor** (framework, check scripts, scopes and API version from `package.json` and `shopify.app.toml`) is a reading checklist; unusual TOML forms may be read differently between runs.
- **Reports** are Markdown by default. The fixed-layout responsive HTML report is gone; Claude writes static HTML only on request, using written escaping rules, and its layout varies between runs. The JSON receipts and stable error codes for programmatic consumers are gone; outcomes are reported in plain language (completed, partial, blocked).
- **Next-action ranking** (blocked milestone, then stale/assumed facts with the 30-day rule, then unfinished milestones, then the last handoff, then planning) is a written table Claude follows rather than a function.
- **Check-in proposals** are written as text fields instead of printed by a command; nothing is ever registered automatically in either edition.
- **Liquid schema ID dedupe** is a manual reading checklist plus the official `shopify theme check`; the one-command scan across a whole theme folder is gone.
- **Cache reset** is a one-line `mv` that renames caches to timestamped `.bak-` copies (same safety: back up, never delete).
- **Apify research input** is filled in from the JSON template in the runbook instead of generated by a script.
- The cross-harness installer (Codex, Cursor, OpenCode, Gemini CLI) is only in the full edition.

## Start here

```text
Use using-shopify-app-builder. I'm new to Shopify apps.
I want to help merchants spot products running low on stock.
Recommend the smallest useful app, explain each step, and verify it on a test store.
Don't run paid services or deploy anything without asking me.
```

Have a project already?

```text
Use using-shopify-app-builder on this repository.
First inspect what is already here, preserve my changes,
and help me get one end-to-end feature working.
```

Only planning? No Shopify or Apify connection is required. Testing an actual app needs a Shopify organization/app/development store. Market research through Apify is optional and may cost money.

## Your local project copilot

Ask naturally: "Continue my app", "What should we do next?", "Show me the evidence". Use the `shopify-project-copilot` skill. It keeps short project facts, decisions, milestones, session handoffs and redacted feedback in `.shopify-app-builder/` inside the app folder you choose (private permissions, an inner ignore file), writes local Markdown reports, and proposes optional check-ins that are never enabled automatically.

## Commands

resume-shopify-app, report-shopify-app, feedback-shopify-app, plan-shopify-check-ins, start-shopify-app, connect-shopify, research-shopify-app, check-shopify-app, init-shopify-app, graphql, add-webhook, audit-scopes, generate-extension, migrate-rest-to-graphql, optimize-listing, validate-idea, deploy-app. Commands are guided instructions, not automatic approval to run their actions.

## Agents

shopify-app-coach, shopify-app-architect, graphql-query-writer, shopify-debugger, shopify-app-ux-reviewer, app-listing-copywriter, shopify-market-researcher, shopify-security-reviewer.

## Safety, privacy and limitations

Paid runs, store writes, scope/access expansion, charges, deployment and submission require explicit task-specific authorization. Claude never reads CLI auth caches or prints secrets.
